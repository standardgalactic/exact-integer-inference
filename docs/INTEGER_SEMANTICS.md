# Integer Reference for SmolLM2-135M: Semantics and First Results

## What exists

scripts/intref.py is a numpy prototype of the integer semantics for the whole model. Matrix products accumulate exactly: operands are widened to float64 for BLAS, which is exact because every partial sum stays below 2^53 (asserted on every call), then converted back to int64. That is a prototype device only; the definition is the integer arithmetic. Information is discarded only at named points: weight quantization, requantization after each linear layer, RoPE rounding, the score requantization, the probability division, the SiLU table, the gated-product rounding, and the norm output rounding.

## Semantics fixed so far

Rounding right shift is (x + 2^(n-1)) >> n with an arithmetic shift, so ties go toward positive infinity, and a non-positive n is an exact left shift. Saturation clips to the signed range of the destination width. Every stored tensor is value = q times 2^-f with f possibly negative. Exact tables are rounded half up from 50-digit mpmath values.

The residual stream is INT32 with 15 fractional bits at every layer, and the embedding lookup writes directly into it. Linear weights are INT8 with one scale per output row, stored as a 14-bit multiplier m in [2^13, 2^14] and a shift n, so each requantization is RS(acc times m, n + f_in - f_out) and the product acc times m stays below 2^63 for every layer shape. The tied embedding matrix is one stored INT8 matrix with one such scale per vocabulary row, used for both the lookup and the output head. Activation formats come from scaling_proposal.json: INT16 with f = 15 - k at unflagged sites and INT32 with f = 31 - k at the 118 flagged site-layers (the gated product takes the finer of that and the resolution its two factors carry).

RMSNorm accumulates the exact sum of squares of the INT32 residual from three INT64 partial sums over the high and low 16-bit halves, adds the constant 6184753 (the epsilon in squared-residual units), and defines the reciprocal root as U = isqrt(2^80 floor-divided by that total). Because the residual cannot exceed the root of its own sum of squares, the product of any residual element and U is bounded by 2^40 for every input, so the following steps need no further overflow analysis. The normalized value is then rounded to 24 bits, multiplied by the INT16 gain, and rounded into the output format.

Attention scores are INT16 with 7 fractional bits (a pure power-of-two shift from the Q and K product, the 1/8 scale included). The exponential table is indexed by the row maximum minus the score in steps of 1/128, holds exp(-d/128) as a 30-bit fraction, and entries beyond a distance of 12 contribute exactly zero. Probabilities are Q0.16 integers from a rounded integer division of each entry by the row sum, with 65536 meaning exactly one. Masked positions are skipped structurally, so no sentinel value is part of the semantics. RoPE tables are Q30 and the rotation is rounded once. SiLU is a 65,536-entry table per distinct format pair, indexed by the INT16 gate value.

## Results

Single blocks at layers 0, 11, 12 and 28, fed the quantized float residual and compared with a float64 block carrying the same dequantized INT8 weights, agree to between 1e-4 and 4e-3 relative RMS at every checkpoint, including layers 11 and 28 where the sink token is written and removed. Maximum errors at those layers are large in absolute steps (tens of thousands at the residual) but are 1e-4 of the sink value itself.

Over eight validation windows (4,088 scored tokens) the float32 baseline scores 3.1523 nats per token. The same model with only the INT8 per-row weights (float arithmetic) scores 3.1587, a KL divergence of 5.9e-3 and 97.0 percent top-1 agreement with the baseline. The wide integer engine scores 3.1585, so its distance from the weight-only float model is a KL of 2.5e-5 with 99.7 percent top-1 agreement: the integer arithmetic adds almost nothing beyond the weight representation. Forcing the residual and the flagged sites onto INT16 per-tensor grids instead scores 3.2731, a KL of 0.107 against the baseline and 82 percent top-1 agreement with the weight-only model. The single-scale INT16 residual is therefore not catastrophic but costs about 0.12 nats per token, roughly twenty times the entire weight-quantization cost.

## Open points and limits

The reciprocal root as defined needs a 128-bit division and integer square root per token; a table-plus-Newton method is acceptable only if it reproduces the same integers, otherwise the definition should change to that method. Score resolution (1/128) bounds attention probability accuracy to about 0.4 percent relative, which accounts for the largest per-checkpoint errors; 8 fractional bits is a candidate with a range of plus or minus 128 against an observed maximum of 78. The narrow comparison mode only rounds the residual at block boundaries and the flagged sites, not the mid-block residual, so it understates the INT16 penalty slightly, and it was not split by site group, so which flagged group causes most of the loss is unmeasured. The per-channel INT16 residual alternative has not been built. The evidence is eight windows of one text source, batch size one, no cached decoding, and positions up to 511 only. No C, CUDA or Metal implementation exists yet; the next artifact is a scalar C reference that reproduces every checkpoint of the numpy prototype exactly, which turns the numpy outputs into the first test vectors.

## Scalar C reference

c/intref.c reimplements the whole model with plain integer arithmetic (INT64 accumulators, __int128 for the norm total and the 2^80 division, an exact digit-by-digit integer square root) and compares every layer's residual and the final logits against the numpy prototype. On two independent vector sets, window 64 with 128 tokens and window 100 with 160 tokens (the 128-token prompt plus 32 continuation positions, recomputed without a cache), all 30 layer residuals and every logit match exactly, in 7 to 10 seconds per sequence at -O2. A deliberately altered expected value (one unit in one residual element at layer 20) is reported at the right index, so the comparison does detect single-unit differences. The expected states are fingerprinted in each vector set's manifest.json.

Two limits on what this establishes. Both implementations were written by the same hand from the same definitions, so agreement shows they implement the stated semantics identically, not that the semantics are the best choice. And the exponential, SiLU and RoPE tables are generated by numpy with mpmath and read by the C program from model.bin; the C program does not regenerate them, so table generation still needs a pinned hash and an independent cross-check before a spec is frozen.
